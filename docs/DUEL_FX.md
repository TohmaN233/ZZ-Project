# 对战特效

对战使用现有 `animationEvents` 队列作为唯一时序来源。`fx-core.js` 只读取事件和
DOM 锚点，不修改规则状态或事件时长。`duel-dom.js` 增量更新原有 HTML，
保留卡牌、手牌槽、Force、布局变量和同一事件的动画节点；页面模板与字符串测试入口保留。
非对战页面仍使用原渲染路径，回放快照不额外播放实时粒子。

格挡取公开阻挡卡的颜色；破坏取 `sourceCard` 的公开颜色，位置仍是
被破坏的 `card`。例如黄／无色互相战死：无色卡承受黄色破坏，黄色卡承受无色破坏。
引擎在离场前冻结来源的 IID、所属方、区域及颜色；同时战死会在任一卡离场前保存双方来源，
避免离场清理或后续触发改变表现。私有区域来源只保留所属方、区域和 `faceDown`，不传身份或颜色。
`destroy.cause` 区分 `battle`、`effect`、`self`、`rule` 和 `replacement`。规则移除和
满场替换采用安静退场；没有来源的旧事件也不猜测攻击颜色。替换不显示“破坏”标签。
手牌、墓地、牌库入场及基地／场地往返均不播放召唤或配置粒子。
`effect` 事件只展示放大卡面和效果正文，不在来源卡或场地中央播放发动粒子。
`effect_target` 的粒子按公开目标 IID／Force／玩家锚点定位，与实际作用对象一致；缺少锚点会记录 FX 错误，不退到场地区域。
召唤／配置声音维持既有判定。
背面卡统一无色，不读取隐藏身份。
攻击宣言发生在 Flash／阻挡之前，不能在目标上先播放命中或扩散冲击圈；实际扣血只由 `damage` 事件播放一次受击与数值。
疲劳通过横置及状态文字表示，卡牌、Force 和效果选牌预览不降低透明度。
生命事件没有公开伤害来源卡，使用独立受击效果，避免猜测来源而泄漏信息。

这不是原游戏效果名的逐项移植。原生格挡 `eff_421`、破坏 `eff_441`、回复 `eff_491`
等引用了未导出的模型，不能完整播放。所选 20 个二进制的纹理依赖齐全，没有模型、声音或
材质依赖；未使用含中文/日文提示字图的效果，以免破坏界面语言选择。平放特效按需要旋转
到屏幕平面，大小、播放速度与颜色矩阵由 manifest 声明。原始二进制和 PNG 不修改。
原素材的绿色不能靠乘色变成蓝色；CSS filter 又会丢弃 alpha 为零的加法光层。
因此原生粒子先绘制到透明 FBO，再用 GPU 矩阵调 RGB、原样保留 alpha。无调色时输出
与原帧一致；普通烟雾仍保留透明遮挡，光束和碎星也不会退化成亮点。

`fx/manifest.json` 声明精确文件清单、SHA-256、来源路径、资源重定向及 40 个语义映射。
150 个二进制/贴图/运行库文件连同清单约 3.49 MB。运行时随产品本地提供，不使用 CDN。
源码/Linux 包按清单及哈希收集；Python package-data 包含 `static/fx/*`；Windows
继续走既有 static 目录打包路径。媒体来源和授权边界见 `THIRD_PARTY_NOTICES.md`。

## 生命周期与排查

- 对局加载页先等待 `ZZFx.prepare()`，再加载对局状态。原生 `context.init` 会同步编译 GPU
  程序：在 Intel UHD / D3D11 冷测中占用约 640ms，原来挤入首个出牌动画并造成约 662ms 帧间隔。
  现在把这项工作放在加载阶段；即使资源迟到，也会等待整批动画结束，不能利用两个连续事件
  之间的瞬时空档初始化。
- FX 独占自己的 WebGL context，原生绘制和调色 pass 各自设置所需状态，关闭 Effekseer
  的外部状态保存／恢复。Intel UHD / D3D11 首帧追踪中，`getParameter(DEPTH_FUNC)` 和
  `getParameter(CULL_FACE_MODE)` 分别阻塞 54.4ms、180.8ms，解释了该帧 236.4ms 的
  原生 draw 停顿；这甚至发生在粒子开始播放之前。小画布预热无法消除这些同步查询，
  因而不保留无效预热。此上下文不能再交给未明确管理绘制状态的其他渲染器。
- 2026-10-23 实测：Intel UHD / D3D11，独立普通 Chrome 窗口，棋盘可见且 21 张图像
  解码完成后首次手牌入场。780ms 飞行在事件后 794.5ms 完成，907.6ms 正常交接队列；
  RAF 最大间隔 29.2ms、P95 4.3ms，200 次原生 draw 最大 2ms，LongTask 和 FX 错误均为零。
  无界面浏览器在首屏挂载后立即启动事件时曾出现 200ms 以上帧间隔，屏蔽原生 draw
  仍能复现，不能据此推断普通窗口中已显示棋盘后的点击性能。
- `onEventStart` 在源节点仍可测量时记录锚点；布局刷新后只启动一次表现。
- 源卡按 IID 匹配事件开始时的快照，控制权转移也从旧方真实位置起飞。破坏卡面与粒子
  共用该中心；入场保留手牌扇形角度与透明度，用 transform 缩放到真实空槽尺寸及横置角度，
  抵达后保持可见直到真实卡接管，不在队列交接前淡出。
- 召唤／配置的卡面沿一条连续二次弧线飞行，全程只使用一次整体缓动；中间采样点线性
  插值，不再逐段 ease-out 后重新起步。回归逐时刻采样真实 WAAPI 卡面中心，检查途中
  是否出现局部速度骤降，避免帧率正常却在固定路径点看似卡住。
- `onEventEnd`/新局/离开对战停止粒子、取消 WAAPI 与待绘帧。已加载资源在同一页面内复用。
- 每个粒子句柄在事件结束前 45ms 终止，末段淡出；异步迟到的资源不跨事件补播。
- 停止动作使待加载回调失效；窗口重新显示也不补播已取消的效果。取消飞行会隐藏残留卡面。
- 空闲没有 FX 帧循环，DPR 上限 1.5；设置“减少动效”、系统偏好、隐藏窗口都会停用动态表现。
  减少动效时保留本次事件的精确伤害/回复数值。
- 失败会写入 `[ZZFx]` console、派发 `zz-fx-error` 并显示可悬停查看原因的 `FX !` 提示。
  不把缺模型、404、WASM 初始化失败当作成功。无 WebGL 时保留正常对局与错误提示；
  WebGL context 丢失后停止粒子，需重载页面恢复。
- DevTools 执行 `ZZFx.inspect()` 查看运行库状态、加载数量、活动句柄、帧循环、迟到跳过数量
  与错误；`phase` 区分运行库加载、等待队列空闲、GPU 初始化、素材加载、ready 和失败，
  `activeOrigins` 提供当前粒子的语义名和棋盘归一化坐标，用于核对目标卡位置；不含隐藏卡身份。
  `initializationMs` 记录本机同步 GPU 初始化耗时；`ready` 仅在所有素材加载完成后为真。
  日志不打印卡牌内容或隐藏信息。

重新导入素材时，先放置官方 1.80.7 的 `effekseer.min.js`、`effekseer.wasm` 及
`effekseer-LICENSE.txt`，再执行：

```powershell
python tools/import_duel_fx.py 'D:\Zenonzard_game\特效包' zz/web/static/fx
```

导入器读取 SKFE 的真实资源表；缺依赖或同名文件内容不一致会失败，不依赖 `files.json`
中可能漏记的模型字段。选择新效果后必须实测原始单位、朝向、屏幕覆盖与时序。

## 验证入口

```powershell
python -m pytest tests/test_frontend_duel_dom.py tests/test_frontend_fx.py tests/test_frontend_fx_arrival.py tests/test_frontend_duel_layout.py -q
python -m pytest tests/test_frontend_atomic_zone_transitions.py tests/test_frontend_visual_settle.py tests/test_duel_visual_timing.py -q
```

GPU 测试逐像素验证加法光层仍存在、alpha 不变、identity 调色不改变 RGB，并检查 WebGL 错误；
同时拦截真实原生 draw 内的状态查询，防止重新引入同步 GPU 读回。
入场覆盖空场、已有卡牌、Base、横置与跨控制方移动。
`test_duel_visual_timing.py` 通过真实选攻击、Flash 放弃、选阻挡操作验证互相战死及来源颜色，
并覆盖暂时颜色离场重置、规则移除、自毁、替换、隐藏来源和普通移动不触发召唤／发动。
Chrome 测试必须能访问本机临时 HTTP 服务。Windows 沙箱若阻止 Chrome crashpad/loopback，
应在允许本机浏览器运行的环境重跑；不能将环境失败当作测试通过。
冷启动竞争回归主动延迟 manifest，在两个连续出牌事件之间检查初始化次数为零，整批结束后
只初始化一次，已结束事件不会迟到补播。
