# ZZ 项目经验：用户确认的规则与实现约束

更新：2026-10-22。适用于全部卡包及同类效果，不能只给例举卡写特判。
来源是本项目用户对真实对局的纠正；有后续澄清时，以后续澄清为准。
本表记录规则及验证入口，不声明某次 Run 或当前代码已经全部通过。

## 工作流如何使用

- 实现、语义验证、修复、独立审查及最终验收都必须读取本文。
- 开始写卡前，找出适用的 ZZ 编号，确认日文完整原文、共享实现和边界场景。
- 在现有 changes/evidence/findings 中简述适用编号和验证结果；无需新造输出字段。
- 场景必须经过真实 `GameSession.choose`，同时验证正确结算和错误选项不出现。
- 不能用“正例跑通”替代规则审查；相关边界未覆盖或证据不足时不能验收通过。
- 修改共享规则后，检查其他卡包中同类效果；不得把公共规则退回逐卡补丁。
- 经验与来源存在尚未解决的冲突时，列出准确原文和分歧，不能自行弱化条件。

## 游戏规则

### ZZ-01 总费用、有色费用与属性分别处理

总费用包含有色部分。ファイアボール总费用为 2、红色要求为 1，不能只支付 1 红即发动。
卡的颜色属性不等于有色费用；有色要求为 0 也不代表无色卡。减费只修改规定部分。
验证：恰好支付、少一个通用费用、颜色不足、减费源失效。

### ZZ-02 无合法效果对象仍可空发魔法

满足时点、费用和其他发动条件时，魔法不能仅因效果无合法对象而禁止使用。
正常支付并按共享魔法生命周期处理进入 Trash，效果能做多少做多少。
这不免除额外费用或其他明确发动条件。覆盖通常时点与 Flash，不能跳过支付。

### ZZ-03 提示选项与结算使用同一合法对象合同

将种类、费用、区域、所属方、实际加护状态等限制声明到共享 `effect_target_filter`。
UI 不得列出全部卡，再在回调里把错误对象变成无事发生；未知过滤器要显式报错。
构筑强化只能从 Trash 选择构筑强化；「霧精」ロゼ只能选满足费用等限制的 Field Minion；
ルビードラゴン只能选实际合法的加护对象，不能把印着 Bless 当作当前已加护。
手牌是未知信息，「天虎」森修这类效果允许按规则选择不发动；明确的放弃入口与非法选牌必须分开。
验证：合法对象出现、近似但不合法对象缺席、可放弃时有独立选项，非法提交不能改变状态。

### ZZ-04 满费用区不取消必发放置；由该区玩家选替换

10 Mana 时，必发的生成或移入费用区效果仍结算，由费用区所属玩家选择覆盖对象。
蓝色将对方卡推回费用区时，也是对方选择自己的替换；不能默认送墓、由施法方代选或无声跳过。
「森獣」ガウディン、コギト・エルゴ・スム适用；后者的移动权消费和魔法进入 Trash 也要完成。
用共享 `place_colorless_mana` 效果模板、`move_to_base_targets` 和容量选择路径实现。
验证：9/10 Mana、双方所属权、多个入区对象和替换先于放置。

### ZZ-05 加护返回与容量按整组计算

Field Minion 返回 Base 时，附着的加护 Mana 必须一并返回并按规则疲劳。
包括マーフォーク探検隊員；不能只返回宿主、把加护留在 Field 或忽略它占用的容量。
复用 `Engine._return_blessings_to_base` 和 `GameSession._base_replacement_groups_for_effect`。
满 Base 的所有替换由所属玩家选择，按宿主及加护的实际入区数一次规划。

### ZZ-06 游戏外生成物离开合法区域即消失

生成的无色 Mana、Minion token 被覆盖或离开其合法区域时消失，不进入 Trash，
也不能算作被放逐的真实卡。它们若实际不进入 Base，不应先要求覆盖 Base 的 Mana。
必须区分 token、真实卡及真实卡效果生成的复制体。

### ZZ-07 加护持续效果严格跟随源和有效条件

「鉄精」アイロナ只在己方回合、仍有效加护且宿主在场时，给己方其他 Minion token +200 BP；
Field Minion 不因此受益。解除加护、宿主离场或切换回合时，相关持续增益随条件失效。
「松精」奥蜜津在 Base 时不能弹出无效的回合开始提示；加护后效果和提示应在正确时点出现一次。
不能把条件型 aura 写成一次性永久修改，也不能把所有未写“本回合”的效果统一在回合末清掉。

### ZZ-08 变身后不能构筑或调试凭空生成，但能合法回手

アンジュ家族的大变身版本、豪炎竜皇等变身后卡面不能直接入卡组，也不能通过 debug 直接加到任意区域。
用户最后澄清：正常变身所得的卡可以回手并再次使用；禁止直接制造不等于禁止合法回手。
通过 `xxxxに変形する` 等原文及 `data/card_transformations.tsv` 维护变身关系，复用 `zz/transformations.py`。
普通构筑检索不提供变身后卡；卡查和游戏详情均允许从原卡私下预览变身链，多形态可左右切换。
预览不得向对手暴露。アンジュ完成大变身的状态不会仅因换区自动恢复；其他重置按各自明确规则处理。

### ZZ-09 真实卡复制不等于 token，也不等于正常召唤

ラヴァ・スライム效果生成的是同名真实卡的复制体，不能替换成近似 token。
复制体保留真实卡的费用、属性和后续区域行为；离场可按真实卡规则进入 Trash。
但由效果放入场不能无条件当作一次正常召唤，导致自身召唤效果无限递归。
场地满时复用真实卡入场的共享容量规则。

### ZZ-10 区分玩家、Force、Minion与原始攻击目标

“攻击玩家时被阻挡”要求原始攻击目标是玩家。噴煙竜ボルカルム攻击 Force 后被挡不触发该条件。
「人鳥精」ペン加护宿主造成伤害后的回复，不能只监听对玩家伤害而漏掉对 Force 伤害。
按原文限定接收者及伤害事件，验证玩家与 Force 两条路径，不自行扩大到未确认的其他对象。

### ZZ-11 生命周期只结算一次，逐句顺序不能交换

直接处理过的出场、破坏或施法来源效果，不能再次被同一事件的全局触发收集重复结算。
ドゥーズアイ破坏时只触发一次，同时保留其他监听者的合法触发。魔法效果结算期间已在 Trash。
「天知」プラトーナ先弃牌再抽牌；「凍械獣」グリフォン先完成抽二动画再开放弃牌选择。
不能交换语句以简化实现，也不能用最终状态相同来忽略中间时点、区域和触发差异。

### ZZ-12 动画快照与区域数量必须一致

每个动画批次拥有自己的起止快照。卡离开源区时从源区移除，落地后加入目标区；
快速连续响应必须串行跨过动画边界，不能把旧事件重放到未来状态。
换手、抽弃、控制权变化和 Mana 替换都适用；不能暂时出现 11 Mana/超额手牌，
也不能靠裁剪数组掩盖错序。即使响应不含事件，也不能越过活动中的批次。

### ZZ-13 卡牌详情应解释实际生效的状态

增益和减益都要能在详情看到来源、数值和有效范围/持续条件；大蔦竜アイヴィーン的对方减益也适用。
计算结果和公开详情复用 `Engine._stat_bonus_effects`，不能一处实际生效、另一处不显示或仍显示过期效果。
提示必须显示对应时点的完整效果正文，不能只有“召唤时/加护时”，也不能在攻击时显示变身效果。

### ZZ-14 完整日文、统一翻译与公开范围

抓取文本可能被截断或缺少「】」；「太陽の竜騎士」オリヴィア等应以日文卡面核对，英文仅交叉检查。
不得根据残文猜数量、费用、目标或条件。保留《付与能力》内嵌【自分のターン】的归属及自然段。
卡查、对局详情和效果提示统一使用完整 `card_japanese_ability`，保留用户已确认的 TSV 中文译文与统一译名。
`見る/見て` 是控制者私看，使用 `prompt.revealedCards`；`公開` 只公开明示的卡，使用共享 public reveal 路径。
不能把私看窗口的全部卡泄露给对手，也不能漏掉原文明示的公开。

### ZZ-15 同名同效果的异画、重印合计限三张

跨卡包的相同日文卡名和完整效果共享 `deck_card_copy_identity`；不能按独立 cardId 各放三张。
构筑添加、计数、保存/载入和 AI 组卡使用同一身份；忽略纯排版差异，不合并实质不同效果。
原文明示不限张数的例外保留，不能被一般三张上限误杀。
EX02/EX02C 的异名对应卡按显式对照表视为同名，合计三张。

### ZZ-16 スイッチ重触发自身标记的效果

指定种族的己方卡召唤时，重触发场上スイッチ卡自身被标记的效果（包括破坏时），不是新卡的召唤效果。
复用触发队列；生成、移动、其他种族、敌方召唤不能误触发。源离场后新召唤不再触发，多源分别处理。

## 工程经验

- **ZZ-E1 公共函数优先**：费用、合法对象、触发、加护返回、容量及生成物生命周期在共享层修复。
  卡模块声明具体参数，不能复制公共逻辑。覆盖正例及用户纠正的反例。
- **ZZ-E2 真实环境验证**：开发机已有资源不能证明新机启动可用。Electron `net.fetch` 手动跳转会报
  `Redirect was cancelled`；资源下载用 `createElectronAssetFetch`/`net.request` 并逐跳校验。
  验证 `tests/electron_asset_transport.test.js` 的真实 Electron 链路，不能仅用 Node fetch mock。
- **ZZ-E3 发布与联机版本**：包内版本、规则校验值、远端服务及下载校验清单分别核对；网页部署成功
  不等于游戏测试通过。同版本替换后用户需重新下载，版本检查不会自动提示；发布/部署须有授权。
- **ZZ-E4 证据与经验分开**：规则结论可以复用，旧测试数量、Run 状态和部署结果不能当作当前证据。
  只重跑受影响的验证；已接受的卡不应仅因无关流程修复全部重写。缺少经验资源时显式报出，不能假装读过。
- **ZZ-E5 高分辨率可玩性**：卡图与交互区按有效视口及场地区域缩放，不能只固定像素导致高分屏上卡牌过小。
  保留用户缩放设置，检查高分辨率、常见桌面尺寸及提示/按钮占位，参见 `tests/test_duel_scale_settings.py`。
- **ZZ-E6 翻译可回填**：待译材料按卡包拆分，卡名和效果各占一行，并包含其他待译内容。
  维护稳定卡 ID 与字段映射再回填 TSV，不用变化后的行号猜对应关系；同步用户修正的参考资料和统一译名。
  复用 `tools/card_translation_exchange.py`，参见 `tests/test_card_translation_exchange.py`。
